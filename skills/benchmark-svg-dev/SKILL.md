# benchmark-svg development

The crate renders one SVG card from canonical benchmark records. Everything below is about changing
it, not using it.

## Layout

```
src/
  lib.rs            module wiring + re-exports
  main.rs           clap CLI: `render`, `formats`
  config.rs         bench-svg.toml via config-rs (file + BENCH_SVG_* env)
  model/            Benchmark, Meta, Report, Unit, UnitKind, formatting
  input/            format detection + json/jsonl/csv/benchmark_test readers
  adapters/         criterion directory and hyperfine JSON importers
  font/             metrics, outline extraction, file resolution
  layout/           pure geometry: taffy tree, badges, sections, row heights
  svg/              emission: theme, atlas, text, rows, legend, cat badge
  render/           orchestration: series union, bar scaling, placeholders
  rows.rs           [[row]] matching, captures, expressions
  expr.rs           arithmetic used by row `value`
  template.rs       `{placeholder|fallback}` expansion
```

Dependencies only flow downwards: `render` -> `layout` -> `svg` -> `font`/`model`. `layout` must not
know about SVG strings; `svg` must not compute geometry.

## Determinism contract

Two machines must produce byte-identical SVGs:

- no clock, no git calls, no randomness, no `HashMap` iteration order in output;
- directory inputs are sorted before parsing (`input::collect_files`, `adapters::criterion::walk`);
- log compression uses `libm`, formatting is explicit (`ryu`), glyph extraction returns results in
  `gids` order even when rayon runs;
- `.gitattributes` forces LF; never commit a CRLF SVG.

## Verify

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets                       # 31 tests
cargo run --example gallery -- --only 14 --png # one asset while iterating
cargo run --example specimen -- --font quicksand
cargo run --example gallery                    # full regeneration (final round)
git status --short -- assets                   # must be empty when nothing changed
```

`gallery` and `specimen` accept `--only`/`--font` (prefix match) and `--list`. Only run the full
regeneration for a final verification; commit code and regenerated bytes together.

## Layout engine

`layout/engine.rs` builds a taffy column: header, one grid per section, footer.

- Grid columns: number, label, bar, value, RME. One `grid_template_rows` entry per row.
- Row height for a multi-source row follows the number of bars actually drawn, floored at
  `card_height` and `NUMBER_BADGE_HEIGHT + 12`; missing sources therefore shorten the row.
- `min_height` is applied after the flex pass by pushing the footer down and setting `plan.height`.
- Columns: label/bar/value widths are clamped to fractions of the content width; keep the clamp bounds
  ordered (`.max(min)`) so narrow widths cannot panic.
- Badges: `layout/badge.rs` computes a cat whose body stretches with the digit count; digits are
  ink-centred, not box-centred.

## Render pipeline

`render/mod.rs` -> `merge.rs`:

1. Build the id union in first-seen order and one slot per series.
2. Choose a reference per row/source/global (`bar_scale`) and a curve (`bar_curve`); single-source
   cards always use the global best with the log curve.
3. Missing slots become `present: false` (`missing = "skip"`) or an empty bar with an em dash.
4. Build `RowPlan`s, then `layout::layout`, then `svg::render`.

## Fonts

`font/` keeps `skrifa` only for parsing; no font is embedded.

- `metrics.rs`: advances, ink boxes, line heights.
- `outline.rs`: `path` cache, `glyph_bounds`, rayon `extract_paths` above 96 glyphs.
- `resolve.rs`: explicit file -> `./fonts/<family>.ttf` -> fontconfig-free defaults.

The gallery defaults to `mplus-rounded`; changing the default font changes every committed asset.

## Config

`Config::load` layers the TOML file with `BENCH_SVG_*` environment overrides through `config-rs`
(`toml` feature only). Add new keys to `Render` with a serde default, update `Default`, document them in
the README and the integration skill, and add a gallery example if the key changes output.

## Gallery and specimens

- `examples/gallery.rs` holds one block per figure (`01-basic` ... `15-bar-scale`).
- `examples/specimen.rs` renders one type specimen per TTF/OTF in `fonts/`.
- New behaviour must land as a new gallery example, generated with the real code path.
- Assets live under `assets/examples/` and `assets/fonts/`; the CI `assets` job regenerates and commits
  them on Linux. Never hand-edit or hand-merge an SVG.

## Release

`.github/workflows/bundle.yml` is one ordered workflow: verify (3 OS) -> byte identity -> assets -> action
test (3 OS) -> build 6 targets -> publish. Tags are `v$(date -u +%Y.%m.%d)-${GITHUB_SHA::7}`; the GitHub
Action installs the binary from the release itself. Marketplace needs a SemVer tag, which date tags are
not.

## Where to change what

| Want | Touch |
|---|---|
| new card element / colour | `svg/theme.rs`, `svg/emit.rs` |
| new geometry rule | `layout/engine.rs` |
| new input format | `input/` or `adapters/`, then `Format` |
| new config key | `config.rs`, `render/`, docs |
| bar scaling policy | `render/merge.rs` (`bar_scale`, `bar_curve`) |
| font metrics | `font/metrics.rs` |
| placeholders / captures | `template.rs`, `rows.rs` |
